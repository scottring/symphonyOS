# Wall-v2 Outgoing Call Interface — Design

**Date:** 2026-06-29
**Status:** Approved (brainstorming → ready for plan)
**Repos:** `symphonyOS` (wall UI + place-call extension), `kid-phone` (listContacts + contactId dialing)
**Builds on:** `kid-phone/docs/superpowers/specs/2026-06-27-beautiful-caller-id-design.md` (inbound caller-ID takeover, the symmetric counterpart)

## Goal

Let a kid place an outbound call from the family wall by tapping a person's face. Tapping a contact rings the in-house corded handset; the kid lifts it and is bridged to the callee. Big, easy-to-press buttons; a confirm step to prevent accidental calls.

## Flow

1. Kid opens the **Phone** screen on wall-v2 (dedicated full-screen mode).
2. Sees a grid of people: **favorites** as large photo buttons up top, **all allowed contacts** below.
3. Taps a face → **confirm overlay** ("Call Grandma?" + photo + big **Call** / **Cancel**).
4. Taps **Call** → kid-phone `initiateCall` rings the in-house handset (`bridgeTo: 'handset'`).
5. The existing `CallerIdTakeover` paints "Calling Grandma…" with her photo.
6. Kid lifts the adjacent handset → Twilio bridges to the callee.
7. Hang up → takeover clears (existing behavior).

**Co-location assumption (confirmed):** the wall sits beside the corded phone, so tap-then-lift is one motion.

## What already exists (do not rebuild)

- `placeCall()` client → `place-call` edge fn → kid-phone `initiateCall` with `bridgeTo: 'handset'`. The ring-handset-then-bridge path is implemented and deployed.
- `current_call` singleton + Realtime + `CallerIdTakeover.tsx` — the "Calling …" overlay, already live on wall-v2.
- Kid-phone allowlist with `{ name, phoneNumber, enabled, photoURL, quietHours }` and contact photos in Firebase Storage.
- Quiet-hours enforcement on `initiateCall`.

## What's new

### 1. Phone screen (symphonyOS, wall-v2)

- New dedicated mode reachable from the wall shell (a "Phone" affordance), rendering a full-screen people grid.
- **Favorites** = large photo buttons at top; **All contacts** = section/expander below. Both come from the same fetched list, partitioned by the `favorite` flag.
- Buttons show name + photo (initial fallback when no photo).
- Tap → confirm overlay → Call/Cancel. No call is placed until Call is tapped.
- Renders from cached last-good contact list so a flaky fetch never blanks the phonebook.

### 2. Contacts data path — live proxy-fetch (kid-phone stays source of truth)

- **New kid-phone endpoint `listContacts`** (secret-gated, reuses `CALL_EVENTS_SECRET`): returns **display fields only** — `{ contactId, name, photoURL, favorite, enabled }`. **No phone numbers leave the backend.**
- **New Symphony edge fn** (or extend an existing one) proxies `listContacts` so the secret stays server-side; the wall calls the proxy via an authenticated Supabase invoke.
- Wall fetches once on Phone-screen open (and caches last-good).
- **Favorites managed** on the kid-phone Contacts tab via a ⭐ toggle (new `favorite: boolean` on contact docs; absent = false).

### 3. Dial path — add `contactId` resolution (allowlist enforcement)

- Extend `placeCall` / `place-call` / `initiateCall` to accept **`contactId`** alongside the existing `toNumber`/`taskId` paths.
- `initiateCall` resolves `contactId` → `{ phoneNumber, name, photoURL }` from the Firestore allowlist, and **rejects if the contact is missing or not `enabled`**. This closes the current gap where outbound dialing does not re-check the allowlist.
- The wall sends only `{ contactId, source: 'kiosk' }`. Raw numbers never reach the browser, and only allowlisted contacts are dialable.
- On success, `initiateCall` publishes the takeover with the resolved name/photo (so "Calling Grandma…" is correct).

## Out of scope (v2)

- **Distinctive ring** ("two quick pulses then pause"). The analog ring cadence is generated by the HT801 ATA, not Twilio. v2 will research HT801 distinctive-ring config keyed off a Twilio-supplied signal (Alert-Info header or a dedicated caller-ID) so the outbound-mode ring differs from a normal inbound ring. v1 ships with the normal ring.
- Agent mode (AI conducts the call) — already gated off in `initiateCall` (Phase 5).
- In-call timer / "On call 0:42" state on the wall — the existing takeover ("Calling…"/connected) is sufficient for v1.

## Security & resilience notes

- Allowlist is enforced server-side via `contactId` resolution; the kiosk cannot dial an arbitrary number.
- Quiet-hours already enforced on `initiateCall` (returns 409); the confirm overlay should surface a friendly "quiet hours" message if the dial is rejected.
- Contact list is cached on the wall; numbers are never cached client-side (the wall never sees them).
- Confirm step prevents accidental calls from an incidental screen touch.

## Testing

- **kid-phone:** unit tests for `listContacts` (secret gate, display-only fields, no numbers) and for `contactId` resolution in `initiateCall` (enabled→dials, disabled/missing→rejects).
- **symphonyOS:** edge-fn proxy test; wall Phone-screen component tests (favorites/all partition, confirm overlay gates the call, cached last-good render, quiet-hours rejection message).
- Manual: tap favorite → confirm → handset rings → lift → connected → hang up → takeover clears.
