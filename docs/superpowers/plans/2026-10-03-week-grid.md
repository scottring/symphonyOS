# Week as a grid — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Week page as a sources band over a days grid, with one row style, one drag rule, the weekend's window work shown once, folded routines, and wider planning pages.

**Architecture:**
- **Pure helpers first.** The weekend split, the fold count and the drag-target rules are pure functions in `src/lib/week/`, unit-tested on their own.
- **WeekJournal does the drawing.** It keeps building days from `journalDays` (WeekViewV2) and gains a `layout: 'grid'` that draws the weekend band and the weekday row.
- **One row component.** A new `WeekRow` replaces the journal entry, the list card and the reference row on /week.
- **Widths.** One CSS custom property sets the shell frame (`--frame-max`), and planning pages raise it.

**Tech Stack:** React 19, TypeScript strict, Vite 7, Tailwind v4, dnd-kit, Supabase. Tests: Vitest + Testing Library (`npx vitest run <path>`; `npm test` is watch mode).

**Spec:** `docs/superpowers/specs/2026-10-03-week-grid-design.md`

## Global Constraints

- **Imports:** use `@/` for imports from `src/`. Node 22.14.0: prepend `$HOME/.nvm/versions/node/v22.14.0/bin` to PATH.
- **Typecheck:** `npx tsc --noEmit -p tsconfig.app.json` (the root tsc is a no-op).
- **Icons:** no emoji; icons come from lucide-react.
- **Copy:** speak like the app. "Sometime this weekend", "once for both days", "Routines · N", "Routines · done".
- **Widths:** planning pages are capped at 1600px. The reading column grows from 992px to 1040px plus the gutter. Phones stay as they are.
- **Folding:** timed routines never fold.
- **Movement:** a calendar event never drags, and a drop on a past day is refused.
- **Data change:** only the nine routines Scott approved. Old rules are recorded first, and it runs in one transaction.
- **Workflow:** never edit the main worktree. Work in `../symphonyOS-week-grid` on `claude/week-grid`.

## Review Focus

1. **A weekend window across the week boundary.** In a Sunday-start week, Saturday and Sunday belong to different weekends, so there is no band; "Sometime" sits with Saturday's weekend. Pinned in Task 2 (`weekendBand`).
2. **A Weekend-rule routine ticked on Saturday** disappears from Sunday and from Sometime. A weekly Sat + Sun routine still needs both ticks. Pinned in Task 2.
3. **A timed task dragged to another day keeps its clock time,** and Undo restores the old day and time. Pinned in Task 4.
4. **The planning width with the side pane open.** The page shrinks within the remaining width and never scrolls sideways. Pinned in Task 1's browser check, plus a CSS-class unit test.
5. **The October band with zero rows** shows its empty line, not a blank band; with 40 rows it scrolls inside the band. Pinned in Task 6.

```ts
export interface WeekendBand { satIndex: number; sunIndex: number }
/** Where the weekend sits in a week's day list: Saturday followed by Sunday, both inside. Null when they are apart (a Sunday-start week) or absent. */
export function weekendBand(days: Date[]): WeekendBand | null
/** Routine occurrences that belong to "Sometime this weekend": a Weekend-rule routine whose weekend occurrence has no day yet and isn't done. */
export function sometimeThisWeekend(args: {
  routines: Routine[]
  weekend: { sat: Date; sun: Date }

  shows: (routine: Routine, day: Date) => boolean   // resolveRoutine(...).shows for that day
}): Routine[]
```
- **What counts.** A routine counts when its `recurrence_pattern.type === 'weekend'`, it shows on Saturday or Sunday, and neither day has it planned or completed.
