# Planning v2 — bringing the app to the prototype

Prototype: `~/Documents/scotts-world/outputs/2026-09-28-symphony-planning-prototype.html`
(Fall / September / Week 38 / Today, reviewed with Scott 2026-09-28).

## What changes, in one paragraph

Each horizon has its **own planning meeting and its own plan**. A planning page
opens on *our plan* — calm, read-only, one toolbar (plan status · view · "Plan
September"). The meeting is an explicit mode with its own stopping point ("This is
our September plan"). The next period's meeting opens by **closing out** the last
one, one card at a time. Every planning page shares one view switch: **List ·
With <level above> · One at a time**. Rows carry production's hover rail (done ·
people · ⋯ Carry / Someday / Drop / All details). Finished and decided cards wear a
stamp. The details panel is the existing one.

## The data model does not change

| Prototype | Production |
|---|---|
| Our plan, agreed on a date | `planning_sessions` row with `notes.savedAt` (`usePlanningSession`) |
| A line on the month | a task committed to the month (`task_commitments`, `selectPeriodTasks`) |
| Done | `completeTask` / `toggleTask` (the completion trigger writes commitment `done`) |
| Carry to October | `keepForward(id, { monthStart: next }, from)` — commitment `carried` |
| Someday | `updateTask(id, { bucket: 'someday' })` |
| Drop (a past period) | `dropCommitment` — commitment `removed`; task falls back to Inbox |
| Drop (the current period) | `deleteTask` — production's current rule |
| Part of a Fall line | `supportsGoalTaskId` / `goalTaskId` via `goalSupport.ts` |
| People | `assignedToAll` through the gated `updateTask` |
| Dates we can't move | all-day and multi-day calendar events (`useDayLoadEvents`) |
| All details | the Details pane (`SelectionProvider` → `TapContextPanel`) |

Open decisions (not blockers): whether "agreed" is joint or per person
(`planning_sessions` is per author); whether Drop on a past period should mean
"let go" rather than "back to Inbox"; hand-pinned landmarks need a flag.

## Design rules settled with Scott (2026-09-28 → 29)

- **One spread per horizon.** Every page wears the same MastheadCard (numeral in the
  margin, "‹ WEEK ›" over the name), one toolbar (plan status · Routines on the week ·
  List / With <level above> / One at a time · the review), then columns that each
  open on the same ruled serif heading. No boxes around columns; the week list's
  cards are the only raised things, because they are what you move. The app's gutter
  (16 / 40 / 56px) on every horizon.
- **Rows are titles.** Done, life area, people and ⋯ fade in on hover; on touch a row
  keeps its title and ⋯. A child row shows "↳ Step toward / Part of …" on hover and
  lights its parent in the reference column.
- **Week is a grid** (2026-10-03): the sources on top (the month's plan, this week's list),
  the days across the full width below — the weekend as one band with "Sometime this
  weekend", the weekdays side by side. See docs/design-system/LAYOUT-SYSTEM.md §8.
- **The reference column** holds the level above and nothing else, and stands first, on
  the left (Scott, 2026-10-03: "source list first"). Routines with no set time left it
  (each day already shows its routines), and the week's **Earlier, not done** moved
  into the week's look-back, after last week's own lines. It replaced the Shelves
  drawer on planning pages (Today keeps its own Shelves).
- **Children are named where they will live.** "+ Next step" / "+ Step" / "+ Add" open a
  draft row on the lower period's list, naming the parent — never a form under the
  parent. Goal → step (`goal_task_id`); plain line → new task with `source_id`; month goal
  → season goal via `supportsGoalTaskId`.
- **Drag.** Week cards → a day (dated) and back to the list (day off, week kept). Month
  lines → a calendar day, a week's number, or back to the list (`lineDropUpdates`; a
  week must never ride with a stated `commitments` list or `planPlacement` drops it).
  A goal is never placed — dropping one creates its next step.
- **The review is the ritual, not a gate.** "Weekly / Monthly / Season / Year review"
  closes out the last period card by card, writes this one with the level above beside
  it, and agrees it. It is prominent only while due (not agreed, or undecided lines
  left). Adding to any list works without it.
- **Add rows carry a life area** (`AddArea`: the area filter wins, else the last choice on
  this device), so a new line never stops its first move to ask "Which domain?".
